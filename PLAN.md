# Світло — виджет отключений света для Pixel (Харьков)

План для Claude Code: от пустого репозитория до рабочего виджета. Выполнять по фазам, после каждой фазы — коммит и короткий отчёт. Если что-то в плане не сходится с реальностью (источник недоступен, формат другой) — остановиться и спросить, а не выдумывать.

## 0. Что строим

```
cron-job.org  ──POST каждые 15 мин──►  GitHub Actions (workflow_dispatch)
                                         │  python backend: Telegram + 1562 + GitHub JSON
                                         ▼
                              status.json в ветке `data` (raw.githubusercontent.com)
                                         ▲
Android (Kotlin, Jetpack Glance) ── WorkManager раз в 15/30/60 мин (можно выключить)
   └─ виджеты 2×2, 4×2, 4×3 + экран настроек + уведомления
```

Ключевые принципы:
- Телефон делает ОДИН лёгкий GET к готовому JSON. Весь парсинг — на сервере.
- Если опрос сервера выключен в настройках — сеть не используется вообще, виджет считает статус локально по последнему сохранённому графику (бейдж «по графику»).
- Сайт облэнерго показывает план, а не факт. Приоритет статуса: авария 1562 → аварийный график (ГАВ) → почасовой график (ГПВ).

## Входные данные от пользователя (спросить в начале)

1. Адрес в формате реестра облэнерго (см. «Формат адреса» ниже) и/или подочередь (например `3.2`).
2. Имя GitHub-репозитория (публичный — чтобы raw-JSON читался без токена).
3. Пакет приложения (по умолчанию `ua.svitlo.widget`).

Ответы (получены): адрес вводится в приложении и в git не хранится (только Repository variable `ADDRESS` / локальный ввод); репозиторий `svitlo`; пакет `ua.svitlo.widget`.

## Фаза 2 — backend (Python 3.12, без тяжёлых зависимостей: httpx, selectolax/bs4, pytest)

### 2.1 Модель
- Время — `Europe/Kyiv`. Час делится на половины (у облэнерго бывают интервалы вида 12:30–16:00).
- `Interval(start, end)` в минутах от начала суток, `end` может быть 1440 («24:00»).
- `DaySchedule(date, queue, off: list[Interval], source, published_at)`.

### 2.2 Telegram-парсер (основной источник графика)
- Парсить HTML веб-превью канала: посты `.tgme_widget_message`, текст + `datetime`.
- Распознавать посты с графиком: строки вида `3.2 09:00-12:30; 16:00-20:00`, тире `-`, `–`, `—`; варианты «не виключається», «24:00»; несколько интервалов через `;` или `,`.
- Дата графика — из текста («сьогодні, 4 березня», «у четвер, 23 жовтня», «на 3 листопада»), иначе из даты поста. Украинские названия месяцев в родительном падеже.
- Несколько постов на одну дату → берём самый поздний (обновлённый график).
- Отдельно ловить сообщения про аварийные отключения (ГАВ, «аварійні відключення») → флаг `emergency_active` + время поста.
- Если в канале несколько страниц — `?before=<id>` до покрытия «вчера…завтра».
- Тесты на фикстурах: минимум 5 реальных постов разных форматов.

### 2.3 GitHub JSON (запасной)
- Формат: `fact.data[<unix_ts дня>]["GPV3.2"][час] ∈ yes|no|first|second|maybe…` — свести в `Interval`-ы.
- Использовать, только если Telegram не дал график на нужную дату.

### 2.4 1562 (факт аварий)
- По результатам Фазы 1. Найти аварию для адреса пользователя: улица + дом (нормализация: «вул.», регистр, апострофы, дроби/литеры дома).
- Результат: `outage_active`, `reason`, `eta` (ориентировочное восстановление), если есть.

### 2.4a Реестр адресов → подочередь
- Облэнерго публикует в Telegram PDF «Адреси та черги» (перечень адресов по подочередям). Парсер находит самый свежий такой PDF в канале, скачивает, извлекает таблицу (pdfplumber) → `address_index.json`: `{нормализованный_адрес: подочередь}` + список улиц для автодополнения в приложении (`streets.json`: тип, название, населённый пункт).
- Если гео-блока нет — дополнительно сверять с формой `gaoinfo` на сайте облэнерго.
- Обновлять реестр при появлении нового PDF (сравнивать по file id/хешу), не чаще раза в сутки.

### Формат адреса (единый для всех источников)
```json
{ "settlement": "м. Харків", "street_type": "вул.", "street": "Сумська", "house": "10", "building": null }
```
- Всё по-украински, как в реестре облэнерго. Тип улицы — из фиксированного списка: `вул., просп., пров., пл., майдан, бульв., в'їзд, тупик, узвіз, шосе, набережна`.
- Номер дома: цифры + необязательная буква (`12А`) или дробь (`3/5`); корпус — отдельным полем.
- Нормализация (backend и Android одинаково): нижний регистр для сравнения, `'` `’` `ʼ` → `'`, ё/э/ы не встречаются — если ввели по-русски, предложить украинский вариант из `streets.json`, латинская/кириллическая «А» в номере дома → кириллица, убрать «буд.», «д.», пробелы.
- Для 1562 и для поиска подочереди используется один и тот же нормализованный ключ `<settlement>|<street_type> <street>|<house>[|<building>]`.
- Адрес задаётся в приложении (экран «Адрес») и передаётся на сервер как Repository variable `ADDRESS` (JSON выше) — сервер работает для одного адреса. Приложение показывает найденную подочередь и статус «распознан 1562 ✓/✗»; если не нашлось — ручной выбор подочереди.

### 2.5 Сведение → `status.json`
```json
{
  "schema": 1,
  "generated_at": "2026-11-16T14:40:00+02:00",
  "queue": "3.2",
  "now": {
    "state": "on | off | unknown",
    "reason": "schedule | emergency | asds1562",
    "since": "…", "until": "…",
    "next_change_at": "2026-11-16T19:00:00+02:00"
  },
  "today":    { "date": "2026-11-16", "off": [["08:00","12:00"],["19:00","22:00"]], "source": "telegram", "published_at": "…" },
  "tomorrow": { "date": "2026-11-17", "off": [["06:00","09:00"]], "source": "telegram", "published_at": "…" } ,
  "emergency": { "active": false, "text": null, "posted_at": null },
  "asds1562":  { "active": false, "eta": null, "text": null },
  "sources": { "telegram": "ok", "github_json": "ok", "asds1562": "blocked" }
}
```
- `tomorrow` = `null`, если график ещё не опубликован (виджет покажет «ещё не опубликован»).
- `history.json` (для календаря): последние 60 дней, по каждому дню — `plan` (финальный график дня) и `fact` (интервалы реальных отключений: из 1562 и, если будет, домашнего датчика). Дописывается при каждом прогоне, старше 60 дней — обрезается. Телефон скачивает его не чаще раза в сутки и при открытии календаря.
- Приоритет `now.state`: `asds1562.active` → `off`; иначе `emergency.active` → `unknown`-с-предупреждением (аварийный график не привязан к очереди); иначе по `today.off`.
- Всё время в выдаче — с офсетом, чтобы телефон не гадал с часовыми поясами.
- Один источник упал → остальные работают, в `sources` пишется статус. Не падать целиком.

### 2.6 Workflow `update.yml`
- Триггеры: `workflow_dispatch` (основной, дергает cron-job.org) + `schedule: '17 * * * *'` (запасной раз в час).
- `concurrency: update` с `cancel-in-progress: false`, timeout 5 мин.
- Публикация: принудительный push одного коммита в orphan-ветку `data` (`status.json`, `history.json`, `address_index.json`, `streets.json`) — история не разрастается. Пушить, только если содержимое (без `generated_at`) изменилось, ИЛИ раз в час (чтобы `generated_at` был свежим).
- Очередь берётся из `vars.QUEUE` и `vars.ADDRESS` (Repository variables), не хардкод.
- URL для телефона: `https://raw.githubusercontent.com/<owner>/<repo>/data/status.json` (CDN кеш ~5 мин — учесть, это нормально).

### 2.7 cron-job.org (`docs/cron-job.md`)
- Fine-grained PAT: только этот репозиторий, права **Actions: Read and write**, больше ничего.
- Задача: `POST https://api.github.com/repos/<owner>/<repo>/actions/workflows/update.yml/dispatches`, каждые 15 мин.
- Заголовки: `Authorization: Bearer <PAT>`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`. Тело: `{"ref":"main"}`. Ожидаемый ответ: `204`.
- Включить уведомления cron-job.org о неудачах.

Критерий готовности Фазы 2: `pytest` зелёный; ручной запуск workflow публикует валидный `status.json`; дергание через curl с PAT даёт 204 и новый прогон.

## Фаза 3 — Android-приложение

Стек: Kotlin, minSdk 31 (Dynamic Color), targetSdk последний стабильный, Jetpack Glance (appwidget + material3), WorkManager, DataStore, Ktor client или OkHttp + kotlinx.serialization. Без Firebase и трекеров.

### 3.1 Данные
- `StatusRepository`: GET JSON → кеш в DataStore/файле. Хранить последний успешный ответ + `fetched_at`.
- `LocalResolver`: по закешированным `today/tomorrow` считает `state`, `next_change_at`, таймер — работает без сети. Используется ВСЕГДА для отображения «сейчас» между опросами (чтобы таймер не врал), а данные сервера (1562/аварии) перекрывают его, если свежие (< 30 мин).
- После полуночи `tomorrow` становится `today` локально.

### 3.2 Фоновая работа и батарея
- Настройка «Получать данные с сервера» (по умолчанию ВКЛ):
  - ВКЛ → `PeriodicWorkRequest` (15/30/60 мин, по выбору), constraints: `NetworkType.CONNECTED`, `requiresBatteryNotLow` если включено «Пауза при заряде ниже 20%». Unique work, `KEEP/UPDATE`.
  - ВЫКЛ → `cancelUniqueWork`, ни одного сетевого запроса. Виджет показывает бейдж «по графику» и «без сети · график HH:MM».
- Перерисовка виджета на границах интервалов без сети: `OneTimeWorkRequest` с `initialDelay` до `next_change_at` (без сетевых constraints), переназначать после каждого срабатывания. Таймер «4:20» обновляется не чаще раза в минуту только когда это дёшево — допустимо обновлять раз в 15 мин + на границах интервалов; текст таймера округлять так, чтобы не вводить в заблуждение («через 4 ч 20 мин» → «≈ 4 ч»), если данные старше 15 мин.
- Кнопка «Обновить» на виджете (иконка в углу 4×2/4×3) → разовый expedited work (только если опрос включён).
- Никаких foreground-сервисов, wakelock-ов и exact alarms.

### 3.3 Уведомления
- Канал «Статус света»: «Свет пропал» / «Свет появился» при смене `state` между опросами.
- Опционально: «Через 30 мин отключение» по графику (локально, без сети).
- Запрос `POST_NOTIFICATIONS` при первом включении.

### 3.4 UI — стиль A «Material You» (утверждён)
Макеты: https://claude.ai/artifact/Emm7vAyoHvqJeQ6TzxTsNv (артборды «Виджеты · стиль A», «Настройки», «Календарь отключений», «Ввод адреса»). Других стилей нет — только A.

Общие правила:
- Цвета — из Dynamic Color (`GlanceTheme` / `dynamicLightColorScheme`). Ниже — эталонные значения для обоев по умолчанию и для fallback на старых API:
  - Свет есть: фон контейнера `#FFE2A3` (≈ `primaryContainer`), текст `#2B1F00` (`onPrimaryContainer`), вторичный текст `#5A4612`, иконка — круг `#2B1F00` с лампой `#FFE2A3`.
  - Света нет: фон `#2C303C` (≈ `surfaceContainerHighest` тёмной схемы), текст `#E6E9F2`, вторичный `#B4BBCC`, круг иконки `#434A5C`.
  - Полоска суток: 24 сегмента, gap 3dp, радиус 3dp, высота 8dp, текущий час — 14dp и контрастный цвет. «Свет есть» `#E3AE3A`, «нет» `#5A4612` (на светлом виджете) / `#F5B83D` и `#4C5468` (на тёмном). Если график с половинками часа — сегмент делится на две половины.
- Скругление виджета 28dp (системный `system_app_widget_background_radius`), внутренние отступы 18–22dp.
- Шрифт: системный (Google Sans на Pixel). Таймер — `tabular-nums`, жирный 40sp (2×2).
- Иконки: лампа / перечёркнутая лампа / календарь (для «по графику») — векторы stroke 2dp.

Размеры (`SizeMode.Responsive`):
- **2×2 (~180×180dp):** круг-иконка сверху, крупный таймер `4:20`, подпись «до отключения» / «до включения», низ — `3.2 · 14:40`. В режиме «по графику» — пунктирный круг с календарём и бейдж «по графику».
- **4×2 (~380×180dp):** иконка + «Свет есть/Света нет» 26sp + «отключение в 19:00 · через 4 ч 20 мин»; полоска суток с подписями 00/06/12/18/24; низ — «Подочередь 3.2» и «обновлено 14:40».
- **4×3 (~380×300dp):** как 4×2, но две полоски: «Сегодня 08–12 · 19–22» и «Завтра 06–09 · 16–19». Если графика на завтра нет — плашка с пунктирной рамкой «График ещё не опубликован — обычно появляется вечером».
- Состояние `unknown`/аварийный график: нейтральный фон, иконка «!», текст «Аварийные отключения — график может не действовать».
- Данные старше 2 ч при включённом опросе: серый текст «нет связи с сервером · HH:MM».
- Тап по виджету → открывает приложение (экран статуса/настроек).

Экран настроек (Compose, Material 3, тёмная/светлая по системе):
- Карточка статуса сверху (тот же стиль, что виджет).
- «Обновление данных»: переключатель «Получать данные с сервера» (подпись меняется: «Раз в 15 мин, в фоне» / «Выключено: виджет считает по последнему графику, батарея не тратится»); при ВКЛ — чипы интервала 15/30/60 мин и переключатель «Пауза при заряде ниже 20%».
- «Календарь»: карточка-превью из 5 строк (3 прошлых дня, сегодня, завтра), каждая — 24 сегмента; сплошные — факт, пунктирные — план. Тап → экран «Календарь».
- «Адрес»: строка с текущим адресом и подочередью, тап → экран «Адрес». URL status.json — в скрытом «Для разработчика».
- «Уведомления»: «Свет пропал / появился», «За 30 мин до отключения».
- Кнопка «Обновить сейчас» и строка «Источники: Telegram ✓ · 1562 ✗».

Экран «Календарь»:
- Месячная сетка (Пн–Вс), под числом — мини-полоска 26×4dp: доля часов со светом (жёлтая) / без света (серая); будущие дни с графиком — пунктирная рамка; дни без данных — приглушённый текст, не нажимаются. Сегодня — жёлтая обводка, выбранный день — заливка `#FFE2A3`.
- Под сеткой — детали выбранного дня: заголовок («Сегодня, 16 ноября»), «без света N ч», 24-сегментная полоска (текущий час выше и белый), список интервалов «08:00–12:00 · Света не было · факт/сейчас/план».
- Листание месяцев свайпом; данные — из `history.json` + `today/tomorrow` из `status.json`. Если опрос выключен — показываем только то, что в кеше, с пометкой «данные на HH:MM».

Экран «Адрес»:
- Подсказка о формате: «пишите по-украински, как в реестре облэнерго: тип улицы + название, дом отдельно; пример: вул. Сумська, 10».
- Поля: «Населённый пункт» (по умолчанию `м. Харків`), «Улица» с автодополнением из `streets.json` (поиск по подстроке, игнорируя тип улицы и апострофы; русский ввод → подсказка украинского варианта), «Дом» (`10`, `12А`, `3/5`, валидация), «Корпус» (необязательно).
- После выбора — карточка результата в стиле «свет есть»: «Подочередь 3.2», «Найдено в перечне адресов Харьковоблэнерго ✓», «Адрес распознан 1562 ✓/✗», дата реестра.
- Если не найдено — сетка 1.1…6.2 для ручного выбора. Кнопка «Сохранить» (жёлтая, на всю ширину).
- Сохранение: адрес и подочередь — в DataStore; приложение показывает инструкцию/кнопку «Скопировать JSON для GitHub» (значение `ADDRESS` для Repository variable), т.к. сервер работает для одного адреса. Автоматическую запись переменной через GitHub API не делать без согласования.
